# 03 — Маршрутизация, каркас приложения и рамка телефона

**What to build:** У приложения появляется понятие «на каком я экране». Маршрутизация на хеше адреса,
без библиотеки: разбор хеша в структуру маршрута и обратная сборка — чистые функции. Роль живёт в
адресе вместе с экраном, поэтому переключение роли — тоже переход.

```
family/bookings              список Booking'ов + кнопка нового Booking'а
family/bookings/new          создание Booking'а
family/bookings/:id          экран одного Booking'а
sitter/bookings              список Booking'ов, входящие запросы первой группой
sitter/bookings/:id          экран одного Booking'а
sitter/schedule              расписание визитов по всем Booking'ам
sitter/earnings              баланс, разбивка по Booking'ам, история Payout'ов
```

Неразобранный или неизвестный маршрут ведёт на список Booking'ов текущей роли.

Каркас переезжает в узкую колонку мобильной ширины, на широком экране — по центру в рамке телефона.
Переключатель ролей остаётся в верхней панели внутри рамки. Панель прототипа — прокрутка времени,
журнал событий, сброс — выносится за пределы рамки: она не часть продукта, и рамка делает это
очевидным без объяснений. У Sitter'а появляется нижнее меню на три пункта.

Содержимое экранов на этом шаге переносится как есть: экраны разделены по маршрутам, но внутренняя
верстка ещё старая и в узкой колонке выглядит тесно. Это ожидаемо — её разбирают тикеты 04 и 05.
Важно, что после этого тикета приложение запускается, по нему можно ходить и ничего не потеряно.

**Blocked by:** 02 — чтобы не переносить между экранами поле, которое всё равно исчезает.
