# 04 — KeyHandover и гейт готовности брони

**What to build:** Family и Sitter согласуют доступ в дом: выбирается способ (личная встреча,
лок-бокс, код домофона), предлагается время и место, и передача считается состоявшейся **только
после подтверждения обеими сторонами**. Пока подтвердила одна сторона, обе видят, чьего
подтверждения ждут. Booking переходит в состояние готовности к старту исключительно когда знакомство
состоялось (или пропущено) и ключи переданы — до этого в карточке видно, какого именно шага не
хватает.

Жизненный цикл (из спеки):

```
KeyHandover: pending → proposed(время + способ) → подтверждения обеих сторон → done
confirmed ──(MeetGreet.happened && KeyHandover(handover).done)──> readyToStart
```

Механизм двусторонний и переиспользуемый: тот же KeyHandover с направлением `return` понадобится
в тикете 08 для возврата ключей. Стоит закладывать направление сразу.

**Blocked by:** 03 — гейт готовности требует обоих предусловий, поэтому делается один раз, когда
MeetGreet уже существует.

**Status:** ready-for-agent

- [ ] Выбор способа передачи доступа: встреча / лок-бокс / код домофона
- [ ] Одна сторона предлагает время и место, вторая подтверждает
- [ ] При подтверждении одной стороной передача НЕ считается состоявшейся; видно, чьего подтверждения ждут (инвариант 8)
- [ ] Booking переходит в готовность только при состоявшемся MeetGreet и переданных ключах (инвариант 2)
- [ ] Пока Booking не готов, в карточке перечислено, каких шагов не хватает
- [ ] У KeyHandover есть направление; вариант `return` заложен в модель, но интерфейса для него пока нет
- [ ] Тесты: односторонее подтверждение не закрывает передачу; гейт готовности не срабатывает без каждого из двух предусловий
