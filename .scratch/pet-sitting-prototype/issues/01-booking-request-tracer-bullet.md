# 01 — Каркас и сквозной срез: запрос брони → принятие / отказ / отмена

**What to build:** Family отправляет Sitter'у запрос на Booking и видит его статус; Sitter видит
входящий запрос и принимает или отклоняет его; Family может отменить Booking до старта. Обе роли
живут в одном приложении с переключателем в хедере и работают на общих данных, поэтому действие
одной стороны сразу видно другой. Состояние переживает перезагрузку страницы, кнопка сброса
возвращает сид-данные (одна Family, один Sitter, один Pet, даты вокруг августа 2026).

Календаря на этом этапе нет — достаточно простой формы с датами и ставкой за визит. Задача среза —
проложить путь через все слои сразу: домен, store, интерфейсы обеих ролей, тесты.

Часы сразу заводятся как зависимость домена, а не `Date.now()` — иначе таймаут из тикета 10 будет
нечем протестировать. Компоненты не содержат переходов: только отправка событий и чтение guard'ов
(ADR 0002).

Жизненный цикл в этой части (из грилл-сессии, см. спеку):

```
requested ──accept──> confirmed
requested ──decline──> declined
confirmed ──cancel──> cancelled
```

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] Приложение запускается командой разработки; переключатель роли Family / Sitter работает
- [ ] Family создаёт Booking с датами, слотами и ставкой за визит; статус запроса виден в её интерфейсе

- [ ] Состояние сохраняется между перезагрузками; сброс возвращает сид-данные
- [ ] Часы — зависимость домена, тесты подставляют своё время
- [ ] Тесты на переходы: принятие, отклонение, отмена, и что отменить нельзя уже отклонённый Booking
