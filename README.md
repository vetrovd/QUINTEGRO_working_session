# Пет-ситтинг — прототип

**[Открыть демку →](https://vetrovd.github.io/QUINTEGRO_working_session/)**

Одноразовый прототип, который проверяет модель взаимодействия между семьёй и ситтером: ситтер
приходит в дом семьи и ухаживает за животным, пока семья в отъезде. Прототип проводит одну
договорённость через весь жизненный цикл — от брони до закрытия и вывода денег — и делает
зависимости между сторонами явными.

Вопрос, ради которого он строился: сходится ли модель. Где стоят обязательные шаги согласования, что
именно разблокирует деньги и что происходит, если одна из сторон молчит.

## Что можно потрогать в демке

Обе роли живут в одном приложении. Переключатель ролей стоит в панели прототипа рядом с рамкой:
стать другим человеком — не действие продукта, а инструмент, которым мы прототип рассматриваем.
В шапке приложения остаётся имя того, чей это экран.

**Семья** бронирует период в календаре, согласует знакомство и передачу ключей, читает отчёты по
визитам и закрывает договорённость.

**Ситтер** видит расписание, отмечает приход, сдаёт отчёт по каждому визиту, видит заработанное с
разделением на заблокированное и доступное и выводит доступное.

Ключевое свойство: **недоступное действие видно как заблокированное**, а не спрятано. Ситтер не
может отметить приход, пока передача ключей не подтверждена обеими сторонами; доступный баланс не
может быть больше нуля, пока договорённость не закрыта.

Рядом с рамкой — панель прототипа; на узком экране она уезжает под неё. Всё, что в ней лежит,
существует только ради демонстрации, поэтому и стоит снаружи:

- **Viewing as** — переключение роли. Обе роли работают на общих данных: действие одной сразу видно
  другой.
- **+1 час / +24 часа** — прокрутка времени. Без неё нечем показать 48-часовое окно
  авто-подтверждения ([ADR 0001](docs/adr/0001-earnings-unlock-on-booking-closure.md)).
- **Журнал событий** — отвечает на вопрос «почему система в таком состоянии», включая отклонённые
  события с причиной отказа.
- **Сбросить к сид-данным** — вернуть всё в начальное состояние.

Данные хранятся локально в браузере, бэкенда нет.

## Как это устроено

Вся логика переходов живёт в `src/domain/` как чистые функции `(state, event) => state` с
guard-предикатами; компоненты только отправляют события и спрашивают у домена, доступно ли действие.
Часы — тоже зависимость домена, а не `Date.now()`. Причины — в
[ADR 0002](docs/adr/0002-pure-domain-reducer-ui-without-logic.md).

```
src/domain/   модель состояний, гарды, деньги — единственный тестовый шов
src/family/   интерфейс семьи
src/sitter/   интерфейс ситтера
src/booking/  шаги договорённости, общие для обеих ролей
src/app/      каркас, переключатель ролей, панель прототипа
```

Термины (Booking, Visit, Handback, Earning, Payout и прочие) используются в строго определённых
значениях — они собраны в [CONTEXT.md](CONTEXT.md). Полная постановка — в
[спеке](docs/spec-pet-sitting-prototype.md).

## Разработка

```bash
npm install
npm run dev        # локальный сервер
npm test           # тесты домена (vitest)
npm run typecheck  # tsc --noEmit
npm run build      # типы + продакшен-сборка в dist/
```

Стек: React 19, TypeScript, Vite, Tailwind 4, Vitest.

## Деплой

Push в `main` запускает [workflow](.github/workflows/deploy.yml): тесты → сборка → публикация на
GitHub Pages. Если тесты падают, деплоя не происходит и на страницу продолжает отвечать предыдущая
версия.
